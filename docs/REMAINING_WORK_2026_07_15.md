# 남은 작업 정리 (2026-07-15 기준)

> 2026-07-15 저녁 갱신: ⑤연차 신청 워크플로(사용자 확정 요구) 추가 · ⑥로컬 500 오류 보고 추가.

## ⑤ 확정된 다음 작업 — 연차 신청 워크플로(Phase 7, 사용자 요구 2026-07-15)

> 기존 "매니저만 등록" 정책을 변경: **연차는 기본적으로 직무지도원이 신청하는 구조**여야 한다.

| # | 요구사항 | 구현 방향 |
|---|---|---|
| 1 | 워커 상단 **사람(프로필) 아이콘** 메뉴에 연차 항목 | 현재 FAB 퀵메뉴 '내 연차'를 프로필 메뉴로 이동/노출(발견성 문제 해결) |
| 2 | 그 화면에서 **발생·사용·잔여** 표시 | 기존 /worker/leave 화면 확장(데이터·API는 이미 있음) |
| 3 | **달력에서 날짜 선택**해 연차 신청 | 신청 모달(달력 피커+일수·사유) → LeaveRequest 신청 레코드 |
| 4 | 신청 → **위탁기관 담당자에게 전달** | ManagerNotice 알림 + 매니저 연차 관리에 신청 인박스(승인=USE 기록/반려=사유 회신) |
| 5 | 매니저 직접 등록도 가능하되 **직무지도원 확인 필요** | 매니저 등록 시 워커에게 확인 요청 알림 → 워커 확인/이의 플로 |
| 6 | 승인된 연차는 **워커 캘린더에 '연차' 표시** | /worker/calendar 에 연차일 배지 렌더 |

- 난이도: **중** (기존 원장·알림·holiday-requests 워크플로 패턴 재사용). 예상 규모: 신청 모델+워커 신청 UI+매니저 인박스+캘린더 표시+확인 플로.
- 참고: 조회 자체는 이미 존재(워커 홈 하단 FAB 퀵메뉴 → '내 연차') — 발견성이 낮아 프로필 메뉴로 이동 예정.

## ⑥ 조사 필요 — 로컬 500 오류 보고(2026-07-15, 사용자 로컬 dev)

```
⨯ SyntaxError: Unexpected end of JSON input (JSON.parse)  page: /manager/leave
⨯ SyntaxError: Unexpected end of JSON input (JSON.parse)  page: /worker/calendar
GET /manager/leave 500 · GET /worker/calendar 500
```

- 1차 소견: **`.next` 빌드 캐시 손상 의심** — 오늘 전혀 수정하지 않은 `/worker/calendar`까지 같은 JSON 파싱 오류로 동시 500인 점, 서버를 여러 번 재기동한 직후인 점이 근거. 앱 코드라면 미변경 페이지가 같이 깨질 이유가 없음.
- 조치 예정: `.next` 삭제 후 재기동 → 재현 여부 확인. 재현되면 스택 전체로 근본 추적.


이번 주까지 완료: 노무사 큐 #1~#7 전량 · 감사 13~21차 전 항목 · 백로그 재감사 소진 · 정식 연차관리 모듈(6단계) · E1-C 서명 슬롯정원 · CSP enforce 전환. **코드는 출시 가능한 상태 — 개발 관점 필수 작업 0건.**
