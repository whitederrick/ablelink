## 0. 문서 사용법

이 문서는 Able-Link를 실제 운영 서비스로 배포하기 전에 필요한 사용 절차와 운영 기준을 정리한 문서다. 단순 기능 소개가 아니라, 각 역할이 어떤 순서로 작업해야 하는지, 어떤 데이터가 생성되는지, 어떤 점을 검증해야 하는지를 함께 적는다.

상태 표기는 다음과 같다.

| 상태 | 의미 |
|---|---|
| 확정 | 현재 코드 기준으로 기능 구조가 비교적 안정적이며 매뉴얼 반영 가능 |
| 검증 필요 | 코드상 기능은 있으나 수정 중이거나 화면/권한/정책 재확인이 필요 |
| 정책 보류 | 노무사, 결제 심사, 개인정보 정책 등 외부 확정이 필요한 항목 |
| 운영 주의 | 기능 사용은 가능하나 개인정보/보안/법적 문서 관점에서 주의 필요 |

이 문서에서 말하는 관리자 구분은 다음과 같다.

| 명칭 | 접속 경로 | 설명 |
|---|---|---|
| 시스템 운영자 | `/admin` | Able-Link 운영 주체. 전체 기관/계정/설정/감사/백업 관리 |
| 위탁기관 관리자 | `/manager` | 위탁기관 담당자. 자기 기관의 현장, 직무지도원, 문서, 급여 관리 |
| 직무지도원 | `/worker` | 현장에서 출퇴근, 일지, 문서, 계약, 급여 확인을 수행하는 사용자 |
| 외부 서명자 | `/sign/*`, `/sign-self/*`, `/contract/*`, `/survey/*` | 토큰 링크로 접근하는 사업체 담당자, 대표자, 계약 서명자, 조사 응답자 |

## 1. 서비스 개요

Able-Link는 장애인 직무지도원 업무를 기관 단위로 관리하는 웹 서비스다. 핵심 가치는 다음 네 가지다.

1. 직무지도원의 근태와 GPS 기록을 표준화한다.
2. 훈련생별 업무일지와 평가 문서를 누락 없이 관리한다.
3. 위탁기관이 공단 제출 문서를 검토, 서명, 발송할 수 있게 한다.
4. 급여 산정과 임금명세서 발행을 출근부/계약/공제 정책과 연결한다.

주요 업무 도메인은 다음과 같다.

| 도메인 | 핵심 데이터 | 주요 사용자 | 산출물 |
|---|---|---|---|
| 현장/배정 | Site, SiteAssignment, TraineePlacement | 운영자, 위탁기관 관리자 | 현장, 직무지도원 배정, 훈련생 배치 |
| 근태 | DailyAttendance, AttendanceIssue | 직무지도원, 위탁기관 관리자 | 출퇴근 기록, 지각/조퇴/미출근/보정 이슈 |
| 일지/평가 | TraineeLog, TraineeEvaluation | 직무지도원, 위탁기관 관리자 | 훈련일지, 적응지도일지, 종합평가 |
| 문서 | DocumentRun, DocumentVersion, SiteSignToken | 직무지도원, 위탁기관 관리자, 외부 서명자 | PDF 문서, 서명본, 제출 이력 |
| 계약 | EmploymentContract | 위탁기관 관리자, 직무지도원 | 전자 근로계약서, 계약 PDF |
| 급여 | PayContract, PayrollRun, PayrollItem | 위탁기관 관리자, 직무지도원 | 급여 run, 급여 항목, 임금명세서 |
| 감사/보안 | AuditEvent, AccessLog | 시스템 운영자 | 변경 이력, 개인정보 접속기록 |

## 2. 전체 업무 흐름

### 2.1 기관 온보딩 흐름

| 단계 | 담당자 | 화면/API | 결과 |
|---|---|---|---|
| 1 | 시스템 운영자 | `/admin/agencies`, `/admin/manager-signup-requests` | 위탁기관 생성 또는 가입요청 승인 |
| 2 | 시스템 운영자 | `/admin/system/agencies/*`, `/admin/manager-signup-requests` | 기관 관리자 계정 생성/초대 |
| 3 | 위탁기관 관리자 | `/manager/settings` | 기관 기본정보, 대표자, 담당자 정보 보완 |
| 4 | 위탁기관 관리자 | `/manager/signature` | 관리자 서명 등록 |
| 5 | 위탁기관 관리자 | `/manager/subscription` | 구독 상태 확인 및 필요 시 결제 |
| 6 | 시스템 운영자 | `/admin/settings`, Vercel env | 알림톡/메일/결제/스토리지 연동 점검 |

출시 전 확인:

- 기관별 `agencyId`가 현장, 배정, 계약, 급여, 문서에 일관되게 연결되는지 확인한다.
- 기관 관리자 계정이 비활성화되면 모든 매니저 API 접근이 차단되는지 확인한다.
- 기관 담당자 정보가 문서 발송 수신처 정책과 일치하는지 확인한다.

### 2.2 현장/직무지도원/훈련생 세팅 흐름

| 단계 | 담당자 | 화면/API | 결과 |
|---|---|---|---|
| 1 | 위탁기관 관리자 | `/manager/sites/new` | 현장 생성 |
| 2 | 위탁기관 관리자 | `/manager/sites/[id]` | 주소, GPS 기준점, 허용 반경, 근무형태 설정 |
| 3 | 위탁기관 관리자 | `/manager/worker-accounts`, `/manager/workers` | 직무지도원 계정 생성/검색 |
| 4 | 위탁기관 관리자 | `/manager/workers`, `/api/admin/assignments` | 직무지도원을 현장에 배정 |
| 5 | 위탁기관 관리자 | `/manager/trainees`, `/manager/sites/[id]` | 훈련생 현황 및 배치 확인 |
| 6 | 직무지도원 | `/worker/select-site` | 멀티현장인 경우 현재 근무 현장 선택 |

데이터 정합성 기준:

- 출퇴근, 일지, 문서, 급여는 모두 배정과 현장 기준으로 연결되어야 한다.
- 멀티현장 직무지도원은 같은 날 오전/오후 다른 현장에서 근무할 수 있으므로, 현장/배정 스코프가 빠지면 문서와 급여가 틀어진다.
- 훈련생 배치 기간은 1:1/1:多 판정과 일지 완료 기준에 직접 영향을 준다.

현재 상태:

- 멀티현장 선택 UI는 코드상 존재한다.
- 실기기에서 로그인 후 현장 선택, 오전/오후 전환, 출퇴근/일지/문서 연결이 정상인지 최종 검증이 필요하다.

### 2.3 일일 근무 흐름

| 시간 | 담당자 | 작업 | 시스템 결과 |
|---|---|---|---|
| 출근 전 | 직무지도원 | `/worker/home`에서 오늘 현장 확인 | 활성 배정과 현장 정보 표시 |
| 출근 시 | 직무지도원 | 출근 버튼 클릭, GPS 권한 허용 | DailyAttendance 생성 |
| 근무 중 | 직무지도원 | 훈련생 지도, 필요 시 메모 | 이후 일지 작성 근거 |
| 퇴근 시 | 직무지도원 | 퇴근 버튼 클릭 | DailyAttendance 종료 시각 기록 |
| 퇴근 후 | 직무지도원 | 훈련생별 일지 작성 | TraineeLog 저장 |
| 검토 | 위탁기관 관리자 | 근태 이슈/일지 누락 확인 | 보정요청, 사유요청, 수정요청 처리 |

근태 상태 기준:

| 상태 | 의미 | 처리 |
|---|---|---|
| 정상 | 현장 범위 내 출퇴근, 지각/조퇴 기준 이내 | 별도 조치 없음 |
| 지각 | 실제 출근이 기준 출근시각보다 늦음 | 임계값 이상이면 이슈 확인 |
| 조퇴 | 실제 퇴근이 기준 퇴근시각보다 빠름 | 사유 또는 보정 요청 |
| 범위외 | GPS 위치가 허용 반경 밖 | 사유 확인 또는 관리자 검토 |
| 퇴근 미실행 | 출근 후 퇴근 기록 없음 | 직무지도원 보정 또는 관리자 표준시각 확정 |
| 미출근/결근 | 근무일인데 출근행 없음 | 월별 현황/캘린더에 합성 표시 |

운영 주의:

- 보정대기 근태는 급여 산정에서 제외될 수 있다.
- 지각 인정 기준은 현장 설정값이 우선이고, 없으면 기관 기본값을 사용한다.
- 결근 합성은 “실제 DB 출근행”이 아니라 표시/검토용 synthetic row일 수 있으므로 CSV/급여/문서에 어떻게 반영되는지 확인해야 한다.

### 2.4 월말 문서 제출 흐름

| 단계 | 담당자 | 작업 | 산출물 |
|---|---|---|---|
| 1 | 직무지도원 | 출근부/일지/평가 작성 상태 확인 | 누락 목록 |
| 2 | 직무지도원 | 문서 미리보기 | PDF preview |
| 3 | 직무지도원 | 본인 서명, 사업체 담당자 서명 수집 | 서명 이미지/토큰 |
| 4 | 직무지도원 | 문서 제출 | DocumentRun/DocumentVersion |
| 5 | 위탁기관 관리자 | 제출 문서 검토 | 확정 또는 변경 요청 |
| 6 | 위탁기관 관리자 | 관리자 서명 적용 | 기관 서명본 |
| 7 | 위탁기관 관리자 | 공단 담당자 이메일 발송 | 제출 이력 |
| 8 | 운영자/관리자 | 필요 시 감사 패키지 생성 | ZIP/PDF 묶음 |

문서 유형:

| 문서 | 기준 데이터 | 필수 확인 |
|---|---|---|
| 직무지도원 출근부 | DailyAttendance, SiteAssignment, TraineePlacement | 현장/기간/근태/서명/1:1 또는 1:多 |
| 지원고용 훈련일지 | TraineeLog PRE/FIELD | 훈련생별 일지 완료 여부 |
| 지원고용 훈련생 종합 평가기록부 | TraineeEvaluation TRAINING | 평가 점수와 의견 |
| 취업 후 적응지도 일지 | TraineeLog ADAPTATION | 적응지도 기간과 일지 |
| 취업 후 적응지도 종합 평가기록부 | TraineeEvaluation ADAPTATION | 평가 점수와 의견 |

출시 전 반드시 확인:

- 출근부 생성 시 같은 직무지도원의 다른 현장 출근행이 섞이지 않는지 확인한다.
- 문서 preview/generate/sign/submit 경로가 모두 같은 payload 규칙을 쓰는지 확인한다.
- 훈련생 ID를 URL로 바꿔도 다른 기관/현장 훈련생 이름이 노출되지 않아야 한다.
- 필수 서명 누락 시 공단 발송이 차단되어야 한다.
- 문서 확정 후 수정본이 들어오면 버전 관리와 제출 이력이 올바르게 남아야 한다.

### 2.5 급여 산정 흐름

| 단계 | 담당자 | 작업 | 결과 |
|---|---|---|---|
| 1 | 위탁기관 관리자 | 급여계약 등록 | PayContract |
| 2 | 위탁기관 관리자 | 근태/보정대기/미확정 확인 | 급여 산정 전 정리 |
| 3 | 위탁기관 관리자 | 월별 급여 run 생성 | PayrollRun DRAFT |
| 4 | 위탁기관 관리자 | 근로일, 시간, 단가, 공제 확인 | PayrollItem |
| 5 | 위탁기관 관리자 | 이상 없으면 확정 | PayrollRun 확정 |
| 6 | 직무지도원 | 급여명세서 조회 | Payslip PDF |

급여 계산에 영향을 주는 요소:

- 배정 기간과 배정 상태
- 출근부 확정 여부
- 보정대기 근태 제외 여부
- 근무형태별 지급시간과 휴게시간
- 현장별 훈련생 수에 따른 1:1/1:多 단가
- 공휴일, 커스텀 휴무, 유급휴일
- 주휴수당
- 소득유형, 4대보험, 공제항목

현재 정책 보류/검증 필요:

- 과거기간 급여 재계산 시 종료/중지/이탈 배정 포함 여부
- 일자별 1:多 판정
- 훈련생 월중 증감
- 주휴수당 전결근주/경계주
- 월급 부분월/유급휴일/결근 차감 정책
- 국민연금/건강보험 자동 승격
- 표준소득월액 등급표
- 같은 기관 재지급/배정별 계약 모델링

급여는 법적/금전 리스크가 있으므로, 운영 전 최소 아래 테스트 월을 만든다.

| 테스트 | 조건 | 기대 결과 |
|---|---|---|
| 단일현장 1명 | 한 현장 훈련생 1명, 정상 출퇴근 | 1:1 단가 |
| 단일현장 2명 | 같은 현장 훈련생 2명 | 1:多 단가 |
| 월중 이탈 | 15일에 훈련생 1명 이탈 | 일자별 판정이 바뀌어야 함 |
| 멀티현장 | 오전 현장 A, 오후 현장 B | 각 현장 인원 기준 단가 |
| 보정대기 | 심한 지각 미확정 | 급여 산정 제외 또는 경고 |
| 공휴일 주 | 평일 공휴일 포함 | 주휴 개근 판정 오류 없어야 함 |
| 전결근주 | 한 주 전체 출근 없음 | 주휴가 부당 지급되지 않아야 함 |

## 3. 시스템 운영자 매뉴얼

### 3.1 운영자 로그인

경로: `/admin/login`

절차:

1. 운영자 계정 ID와 비밀번호를 입력한다.
2. 로그인 성공 시 `/admin`으로 이동한다.
3. 로그인 후 전체 기관의 운영 현황을 확인한다.

운영 기준:

- 운영자 계정은 최소 인원만 발급한다.
- 퇴사/권한 변경 시 즉시 비활성화한다.
- 운영자 계정의 비밀번호 초기화 이력은 감사로그로 추적한다.

### 3.2 위탁기관 관리

경로:

- `/admin/agencies`
- `/admin/agencies/[id]`
- `/admin/manager-signup-requests`

주요 작업:

| 작업 | 설명 | 확인사항 |
|---|---|---|
| 기관 생성 | 위탁기관 기본정보 등록 | 기관명, 사업자정보, 연락처 |
| 기관 수정 | 주소, 담당자, 구독 정보 수정 | 기존 문서/계약 영향 확인 |
| 가입요청 승인 | 기관 관리자 가입신청 승인 | 사업자 서류, 담당자 정보 확인 |
| 가입요청 반려 | 보완 필요 또는 부적합 신청 반려 | 반려 사유 기록 |
| 관리자 초대 | 기관 관리자 계정 발급 | 이메일/알림톡 발송 여부 |

운영 주의:

- 기관 삭제보다는 비활성화를 우선한다.
- 이미 계약/출근부/문서가 있는 기관은 데이터 보존 정책을 확인해야 한다.
- 사업자등록증 등 업로드 파일은 private storage와 접근권한을 확인한다.

### 3.3 시스템 관리자 계정 관리

가능 작업:

2. 대시보드 프로모션은 기관 관리자 화면에 노출되는 안내 배너로 사용한다.
3. 지원 요청은 기관 관리자가 올린 문의/수정 요청을 확인하고 회신한다.

지원 요청 처리 기준:

- 개인정보가 포함된 첨부파일은 다운로드 후 로컬 보관을 피한다.
- 회신 내용에는 비밀번호, 토큰, 계좌번호 전체를 쓰지 않는다.
- 장애 조치가 필요한 경우 내부 이슈로 연결한다.

변경 원칙:

- 운영 설정 변경 후 1분 캐시 때문에 즉시 반영되지 않을 수 있다.

경로:

- `/admin/audit`

백업 운영:

- 다운로드 권한은 시스템 운영자로 제한한다.
- 다운로드 후 저장 위치와 보관 기간을 별도 관리한다.
- 운영 DB 백업을 개발/테스트 환경에 복원할 때는 개인정보 마스킹 원칙을 따른다.

감사로그 확인:

- 누가, 언제, 어떤 모델/대상을 생성/수정/삭제했는지 확인한다.
- 민감 필드가 원문으로 남지 않는지 주기적으로 샘플링한다.

개인정보 접속기록 확인:

- 취급자 유형, 취급자 계정, 정보주체, 접속지 IP, 수행업무, 경로를 확인한다.
- CSV 다운로드 기능은 운영자 전용이어야 한다.
- 개인정보 처리방침의 접속기록 보존기간과 시스템 보관 정책을 일치시킨다.

- `/manager/worker-accounts`
- `/manager/workers`

가능 작업:

- 직무지도원 검색
- 신규 계정 생성 또는 초대
- 임시 비밀번호 발급
- 전화번호/이름 등 기본정보 보완
- 계정 활성 상태 확인

운영 기준:

- 전화번호는 로그인 ID로 쓰일 수 있으므로 중복 여부를 확인한다.
- 비밀번호 초기화 후 임시 비밀번호 전달 경로를 안전하게 관리한다.
- 기존 직무지도원을 새 현장에 배정할 때는 현재 다른 현장 배정 상태를 확인한다.

### 4.4 배정 관리

경로:

- `/manager/workers`
- `/manager/assignment-selection`
- `/api/admin/assignments`

배정 생성 시 확인:

| 항목 | 설명 |
|---|---|
| 직무지도원 | 계정과 전화번호 확인 |
| 현장 | 본인 기관 소속 현장인지 확인 |
| 시작일/종료일 | 급여/문서 기간에 영향 |
| 근무형태 | 오전/오후/전일/커스텀 |
| 출퇴근 버튼 면제 | 자동기록 대상 여부 |
| 계약 연결 | 근로계약서와 배정 연결 여부 |

배정 상태 처리:

- `ASSIGNED`: 배정 생성 또는 요청 상태
- `CONFIRMED`: 계약/연결 등 사전 조건 확인 상태
- `ACTIVE`: 실제 근무 활성 상태
- `PAUSED`/`DROPOUT` 등: 중지 또는 이탈 상태

멀티현장 주의:

- 직무지도원이 둘 이상의 활성 배정을 가지면 워커 앱에서 근무 현장을 선택한다.
- 오전/오후 다른 현장에서 근무하는 케이스는 출근부와 급여에서 현장별로 분리되어야 한다.

### 4.5 근태 운영

경로:

- `/manager/attendances`
- `/manager/calendar`
- `/manager/inbox/attendance`
- `/manager/attendance-edit-requests`

일일 확인 절차:

1. 근태 현황에서 오늘 출근/퇴근 완료 여부를 확인한다.
2. 지각, 조퇴, 범위외, 퇴근 미실행 상태를 확인한다.
3. 이슈가 있으면 근태 이슈 확인 화면에서 상태를 본다.
4. 필요한 경우 직무지도원에게 사유 등록 또는 시각 보정을 요청한다.
5. 직무지도원이 제출한 수정 요청은 근거 확인 후 승인/반려한다.

근태 이슈 처리 기준:

| 이슈 | 관리자 조치 |
|---|---|
| 지각 | 인정 기준 초과 여부 확인, 사유 요청 |
| 조퇴 | 실제 근무 종료 사유 확인 |
| 범위외 | 위치 사유 확인 또는 현장 GPS 재검토 |
| 퇴근 미실행 | 직무지도원 보정 요청, 장기 미처리 시 표준 퇴근시각 확정 |
| 수정 요청 | 증빙/사유 확인 후 승인 또는 반려 |

월말 확인:

- 미출근/결근 표시가 실제 근무일 기준인지 확인한다.
- 출근부 확정 전 보정대기 상태가 남아 있지 않은지 확인한다.
- 급여 산정 전 근태 이슈를 모두 처리한다.

### 4.6 일지 운영

경로:

- `/manager/logs`
- `/manager/reports`

확인 기준:

- 근무일별 일지 작성 여부
- 훈련생별 일지 완료 여부
- 훈련 유형: PRE/FIELD/ADAPTATION
- 수행 과업과 평가 점수
- 1:多 현장의 훈련생별 누락 여부

처리 기준:

- 1:1 현장은 해당일 해당 훈련생 일지 1건이 완료되어야 한다.
- 1:多 현장은 해당일 배치된 훈련생 수만큼 완료되어야 한다.
- 주말/휴일 일지는 사유와 실제 근무 여부를 확인한다.

### 4.7 문서함 운영

경로:

- `/manager/documents`
- `/manager/gov-submissions`
- `/manager/docs`

문서 검토 절차:

1. 문서함에서 제출 상태를 확인한다.
2. 직무지도원, 현장, 기간, 문서 유형을 확인한다.
3. PDF 미리보기로 내용과 서명을 확인한다.
4. 출근부는 출근일/결근/지각/조퇴/1:1 또는 1:多 표기가 맞는지 확인한다.
5. 일지는 훈련생별 작성 내용이 누락되지 않았는지 확인한다.
6. 오류가 있으면 변경 요청을 보낸다.
7. 이상 없으면 확정한다.
8. 관리자 서명을 적용한다.
9. 공단 담당자에게 발송한다.
10. 제출 이력에서 발송 완료를 확인한다.

필수 확인표:

| 확인 항목 | 출근부 | 일지 | 평가 |
|---|---|---|---|
| 기간 | 필수 | 필수 | 필수 |
| 현장 | 필수 | 필수 | 필수 |
| 직무지도원 | 필수 | 필수 | 필수 |
| 훈련생 | 해당 없음 또는 현장 인원 판정 | 필수 | 필수 |
| 서명 | 직무지도원/사업체/관리자 정책 확인 | 문서별 정책 확인 | 문서별 정책 확인 |
| 누락 | 미출근/퇴근누락/보정대기 | 미작성 일지 | 미작성 평가 |

공단 발송 전 차단해야 하는 상태:

- 관리자 서명 없음
- 직무지도원 필수 서명 없음
- 사업체 담당자 필수 서명 없음
- 문서 기간과 실제 배정 기간 불일치
- 다른 현장 출근행 혼입
- 다른 기관/현장 훈련생 이름 혼입
- 변경 요청 중인 문서

### 4.8 급여 운영

경로: `/manager/payroll`

급여계약 등록 시 입력:

- 직무지도원
- 급여유형: 시급/일급/월급
- 기본 단가
- 1:多 단가
- 소득유형
- 주휴수당 정책
- 보험/공제 설정
- 계좌정보 확인 상태

급여 run 생성 전 확인:

- 해당 월 출근부가 모두 정리되었는지
- 보정대기 근태가 남아 있지 않은지
- 월중 배정 시작/종료가 맞는지
- 훈련생 수 변동이 반영되는지
- 휴일/커스텀휴무가 등록되어 있는지
- 급여계약이 해당 기간에 유효한지

확정 전 검토:

- 총 근무일수
- 총 지급시간
- 단가 적용
- 주휴수당
- 휴일/야간/연장 가산
- 소득세/지방세
- 4대보험
- 기타 공제
- 실지급액

운영 주의:

- 급여 확정 후 정정은 감사로그와 사유를 남긴다.
- 급여 산정 정책이 확정되지 않은 항목은 “보류”로 표시하고 자동공제에 반영하지 않는다.

### 4.9 계약서 운영

경로:

- `/manager/contracts`
- `/contract/[token]`

계약 생성 절차:

1. 직무지도원을 선택한다.
2. 현장 또는 배정을 연결한다.
3. 계약 기간을 입력한다.
4. 근무장소, 근무형태, 근무시간, 임금을 입력한다.
5. 계약서 템플릿과 특약을 선택한다.
6. 직무지도원에게 서명 링크를 발송한다.
7. 서명 완료 후 계약 상태를 확인한다.
8. 필요한 경우 관리자/대표자 서명을 적용한다.
9. PDF를 저장/다운로드한다.

주의:

- 계약 내용은 급여, 배정, 출퇴근, 문서의 기준 데이터가 될 수 있다.
- 계약서 서명 후 배정 상태가 자동 전환되는지 확인한다.
- 기존 직무지도원에게 새 배정을 연결하는 경우 인증코드 알림톡 설정이 필요하다.

### 4.10 기관 공지와 지원 요청

경로:

- `/manager/announcements`
- `/manager/system-notices`
- `/manager/notices`
- `/manager/support`

공지 운영:

- 기관 공지는 소속 직무지도원에게 노출된다.
- 공지 작성 시 개인정보를 포함하지 않는다.
- 긴급 근무 안내, 월말 문서 마감, 시스템 장애 안내 등에 사용한다.

지원 요청:

- 시스템 운영자에게 문의/수정 요청을 보낸다.
- 첨부파일에는 필요한 최소 자료만 포함한다.
- 주민등록번호 등 불필요한 민감정보는 첨부하지 않는다.

## 5. 직무지도원 매뉴얼

### 5.1 로그인과 온보딩

경로:

- `/worker/login`
- `/worker/onboarding`
- `/worker/connect`
- `/worker/select-site`

로그인 절차:

1. 전화번호 또는 발급받은 ID를 입력한다.
2. 비밀번호를 입력한다.
3. 임시 계정이면 온보딩 화면에서 비밀번호를 변경한다.
4. 새 배정 연결이 필요한 경우 인증코드를 입력한다.
5. 여러 현장에 배정되어 있으면 오늘 근무할 현장을 선택한다.

주의:

- 현장 선택을 잘못하면 출근부, 일지, 문서가 잘못 연결될 수 있다.
- 현장 선택 화면이 뜨면 반드시 오늘 근무지 기준으로 선택한다.

### 5.2 출근/퇴근

경로: `/worker/home`

출근 절차:

1. 홈 화면에서 현장명과 근무시간을 확인한다.
2. 출근 버튼을 누른다.
3. 브라우저 위치 권한을 허용한다.
4. 출근 완료 메시지와 상태를 확인한다.

퇴근 절차:

1. 근무 종료 후 퇴근 버튼을 누른다.
2. 위치 권한이 다시 필요하면 허용한다.
3. 퇴근 완료 상태를 확인한다.
4. 업무일지를 작성한다.

문제 발생 시:

| 상황 | 조치 |
|---|---|
| 위치 권한 거부 | 브라우저 설정에서 위치 권한 허용 |
| 현장 범위 밖 | 실제 위치 확인 후 관리자에게 사유 설명 |
| 출근/퇴근 시각 오류 | 출근부 수정 요청 제출 |
| 퇴근 누락 | 늦은 퇴근 처리 또는 관리자 요청에 응답 |

### 5.3 업무일지 작성

경로:

- `/worker/worklog`
- `/worker/worklog/batch`
- `/worker/logs`
- `/worker/logs/missing`

작성 절차:

1. 작성할 날짜와 훈련생을 선택한다.
2. 훈련 유형을 확인한다.
3. 지도시간, 과업, 수행 평가, 내용을 입력한다.
4. 필요 시 음성 녹음으로 AI 초안을 생성한다.
5. AI 초안은 반드시 검토하고 수정한다.
6. 저장 후 완료 상태를 확인한다.

AI 음성 일지 주의:

- 음성과 훈련생명이 외부 AI 서비스로 전송될 수 있다.
- 민감한 의료정보, 주민등록번호, 불필요한 개인정보는 녹음하지 않는다.
- AI 결과가 사실과 다르면 직접 수정해야 한다.

1:多 현장 작성 기준:

- 한 명의 직무지도원이 여러 훈련생을 지도하는 날에는 훈련생별 일지를 각각 작성한다.
- 일부 훈련생만 작성하면 관리자 화면에서는 미완료로 처리될 수 있다.

### 5.4 문서 생성과 제출

경로:

- `/worker/docs`
- `/worker/docs/view`
- `/worker/docs/preview`
- `/worker/signature`

제출 절차:

1. 문서 메뉴에서 기간을 선택한다.
2. 문서 유형을 선택한다.
3. 미리보기로 내용을 확인한다.
4. 직무지도원 서명이 필요한 경우 서명을 등록한다.
5. 사업체 담당자 서명이 필요한 경우 서명 링크를 발급한다.
6. 모든 필수 서명이 준비되면 제출한다.
7. 제출 후 위탁기관 관리자 검토를 기다린다.

제출 전 체크:

- 기간이 맞는가
- 현장이 맞는가
- 출퇴근 기록이 누락되지 않았는가
- 훈련생별 일지가 모두 작성되었는가
- 서명이 누락되지 않았는가
- 지각/조퇴/결근 사유가 필요한 날이 남아 있지 않은가

### 5.5 계약서 서명

경로:

- `/contract/[token]`
- `/worker/contracts`

절차:

1. 알림톡 또는 링크로 계약서 페이지에 접속한다.
2. 계약 기간, 근무장소, 근무시간, 임금, 특약을 확인한다.
3. 내용이 맞으면 서명한다.
4. 제출 후 서명 완료 메시지를 확인한다.
5. 워커 앱 계약서 메뉴에서 계약 이력을 확인한다.

주의:

- 계약 내용이 실제 근무조건과 다르면 서명 전 위탁기관에 문의한다.
- 서명 링크는 만료될 수 있다.
- 이미 사용한 서명 링크는 재사용할 수 없다.

### 5.6 수정 요청과 휴무 요청

주의:

- 허위 사유 제출은 기관 정책에 따라 제재될 수 있다.

## 6. 공개 토큰 페이지 운영

### 6.1 계약서 서명 페이지

경로: `/contract/[token]`

사용자:

- 직무지도원

정상 조건:

- 토큰이 유효해야 한다.
- 계약서가 만료되지 않아야 한다.
- 이미 서명 완료된 계약이 아니어야 한다.

- 서명 입력 UI
- 서명 완료 결과

검증 포인트:

- 다른 계약 토큰을 추측할 수 없어야 한다.
- 서명 후 계약 상태가 정확히 변경되어야 한다.
- 배정 연결/알림톡 후속 처리가 실패해도 계약 서명 자체의 상태가 불일치하면 안 된다.

### 6.2 사업체 담당자 서명 페이지

경로: `/sign/[token]`

사용자:

- 사업체 담당자
- 공단 담당자 등 문서별 외부 서명자

검증 포인트:

- 만료 토큰 차단
- 사용 완료 토큰 차단
- 동시 제출 시 중복 서명 방지
- 서명 이미지 접근통제
- rate limit

### 6.3 관리자 본인 모바일 서명 페이지

경로: `/sign-self/[token]`

사용자:

- 위탁기관 관리자
- 기관 대표자

용도:

- PC에서 토큰 발급 후 스마트폰에서 직접 서명
- 관리자 서명 또는 대표자 서명을 계정/기관 프로필에 저장

주의:

- 토큰은 일회용이어야 한다.
- 대표자 서명은 계약서에 자동 삽입될 수 있으므로 권한과 저장 정책을 명확히 한다.

### 6.4 만족도 조사

경로: `/survey/[token]`

사용자:

- 평가 결과 공유 여부는 정책에 따라 관리한다.

## 9. 보안/개인정보 운영 기준

### 9.1 개인정보 분류

| 분류 | 항목 | 관리 기준 |
|---|---|---|
| 일반 개인정보 | 이름, 전화번호, 이메일 | 최소 노출, 마스킹 |
| 민감 운영정보 | 계좌번호, 생년월일, 서명 | 접근권한 제한, 감사로그 |
| 위치정보 | 출퇴근 GPS | 수집 고지, 목적 제한 |
| 훈련생 정보 | 이름, 장애유형, 보호자 연락처, 평가 | 기관 스코프 제한, 외부 전송 주의 |
| 문서정보 | 계약서, 출근부, 평가서 PDF | private storage, 다운로드 이력 |
| 인증정보 | 비밀번호, 토큰, 인증코드 | 해시/일회용/만료 |

### 9.2 접근통제 원칙

- 시스템 운영자는 전체 데이터 접근 가능. 단, 접속기록과 감사로그가 남아야 한다.
- 위탁기관 관리자는 자기 기관 `agencyId` 범위만 접근 가능해야 한다.
- 직무지도원은 본인 workerId와 활성 배정 범위만 접근 가능해야 한다.
- 공개 토큰 페이지는 토큰이 권한 역할을 하므로 만료/일회용/rate limit가 필수다.
- 훈련생 ID, 문서 ID, 급여 item ID 등 URL 파라미터는 항상 소속 검증을 해야 한다.

### 9.3 로그 기준

서버 로그에 남기면 안 되는 정보:

- 비밀번호 원문
- 인증코드 전체
- 계좌번호 전체
- 서명 이미지 data URL
- 토큰 전체
- 주민등록번호 등 법정 민감정보
- 음성 원문 또는 AI prompt의 과도한 개인정보

감사로그 마스킹 대상:

- password, passwordHash
- signatureUrl 계열
- accountNumber
- ciKey
- verifyCode
- birthDate
- phoneNumber
- guardianPhoneNumber
- bankName, accountHolder
- businessNumber
- token, signToken

### 9.4 공개 업로드 기준

공개 업로드 endpoint는 다음을 만족해야 한다.

- 파일 크기 제한
- MIME allowlist
- magic-byte 검증
- private bucket 저장
- rate limit
- 확장자 spoofing 방지
- 다운로드 권한 검증
- 악성 파일 대응 정책

### 9.5 CSRF/세션 기준

현재 세션 쿠키는 httpOnly, production secure, SameSite=Lax 구조다. 출시 전 다음을 검토한다.

- 관리자/매니저/워커 mutation API의 Origin/Referer 검증
- 고위험 API의 CSRF 토큰
- 로그아웃/비밀번호 변경/계좌 변경/문서 발송/급여 확정의 추가 확인
- 공개 토큰 POST의 rate limit

## 13. v1.0 확정 방법

최종 매뉴얼은 다음 조건을 만족하면 v1.0으로 올린다.

1. Claude 수정분이 모두 커밋되었다.
2. Codex 재감사에서 P0/P1 차단 이슈가 해소되었다.
3. 빌드와 핵심 테스트가 통과했다.
4. 운영 환경변수와 외부 연동 값이 확정되었다.
5. 실제 모바일/데스크톱 화면 검증이 완료되었다.
6. 급여 정책 중 보류 항목이 명확히 “자동화 제외” 또는 “확정 반영”으로 분류되었다.
7. 개인정보처리방침, 이용약관, 환불정책, 가격 페이지가 실제 기능과 일치한다.

v1.0 작성 시 추가할 것:

- 실제 화면 캡처
- 메뉴별 버튼명
- 관리자 교육용 시나리오
- 직무지도원용 1페이지 빠른 가이드
- 장애 대응 연락망
- 월말 마감 운영표
- 개인정보 처리 내부 점검표
