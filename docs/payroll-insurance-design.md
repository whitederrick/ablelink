## 🎯 목표 (North Star) — 위탁기관 담당자 핵심 편의 기능

**급여 계산과 명세서 발급을 "한 번 클릭(또는 무클릭)"으로 자동화**한다. 담당자가 매월 손으로 계산·세금·보험·명세서를 만들지 않게 하는 것이 이 기능의 존재 이유.

이상적 월 흐름(담당자 관점):
1. (사전 1회) 근로계약서 서명 완료 → **급여 기준 자동 생성**(시급·기간·소득유형 프리필). 담당자는 확인만.
2. 매월 마감일 → 출근부(확정분)·급여 기준·공제·**보험/소득 자동 판정**으로 **급여 자동 계산(DRAFT)**.
3. 담당자는 **검토 화면에서 이상치만 확인** → "확정" 1클릭.
4. 확정 즉시 **명세서 PDF 자동 생성 + 직무지도원에게 발급(앱 내 무료)**. (필요 시 다운로드·발송)

→ 5번(급여 기준 연결)·6번(보험/소득 자동 판정)은 모두 이 **자동화의 정확도·무손질**을 위한 선행 작업이다.
이미 존재: 월별 run 계산(`runs/route.ts`), 명세서 페이로드(`lib/payroll/payslipPayload.ts`)·발급 API(`items/[itemId]/payslip`).
부족: ① 수동 입력 과다(급여 기준) ② 보험 차등 미반영(과/오공제) ③ 명세서 자동 발급/전달 동선 ④ 매월 자동 트리거.

## 0. 현재 상태 (as-is)

- **계약이 2종 공존**
  - `EmploymentContract` (근로계약서, `/manager/contracts`, PRO): 법적 문서·PDF·서명. 배정 파이프라인(ASSIGNED→CONFIRMED).
  - `PayContract` (급여 관리 "계약 등록"): 급여 계산 기준 마스터. **워커 직접 선택 + 전부 수동 입력**.
- **연결 거의 없음**: 급여 계산(`runs/route.ts`)은 `EmploymentContract`에서 `workDaysPerWeek`(주휴 소정근로일수)만 가져옴. 시급·기간은 `PayContract`에 따로 손입력 → **이중 입력·불일치(drift) 위험**.
- **공제 산정**(`runs/route.ts`)
  - `incomeType === BUSINESS` → **사업소득세 3.3%만**.
  - `incomeType === EMPLOYMENT` → 간이세액표 소득세 + 주민세(소득세 10%) + **4대보험 일괄**(국민연금·건강·장기요양·고용; `InsuranceRates`).
  - **일용/초단시간/단시간 차등 없음**. EMPLOYMENT면 무조건 4대보험 전액.
  - **산재 없음**(worker 공제 대상 아님 — 전액 사업주 부담. `InsuranceRates`에도 산재 요율 컬럼 없음).
  - 주휴수당: EMPLOYMENT 단시간만, 2조건(주 개근 + 4주 평균 15h↑) 자동(또는 `PayContract.weeklyHolidayPay` 고정 오버라이드).

## 1. Part A — 급여 기준 ↔ 근로계약서 연결 (항목 5)

### 문제
1. 이름 충돌: "계약 등록"이 법적 근로계약서와 혼동.
2. 이중 입력: 시급·기간을 근로계약서·급여 기준 양쪽에 입력 → 불일치.
3. 연결 없음: 급여 기준이 근로계약서에서 자동으로 안 채워짐.

### 제안
1. **명칭 정리(UI만)**: "급여 계약" → **"급여 기준"**, "계약 등록" → "급여 기준 등록". (모델명 `PayContract`는 내부 유지)
2. **근로계약서에서 프리필**: 워커 선택 시, 해당 워커의 **유효(서명 완료·기간 겹침) 근로계약서**에서 공통 필드를 끌어와 자동 채움.
   - 채움: `시급/일급/월급액 → baseAmount`, `계약기간 → effectiveFrom/To`, `근무형태`.
   - **소득유형·4대보험 가입은 수동 선택이 아니라 자동 판정**(§2). 급여 기준 폼에서 `소득유형`·`내부/외부` 선택 **제거**.
   - 2명+시급(시급×120%)·주휴수당은 시급에서 자동 산식 → 직무지도원 급여 기준은 사실상 **전부 자동 + 확인**.
   - 템플릿이 여러 종이어도 **공통 필드만** 읽으므로 템플릿 무관.
3. **불일치 가드**: 급여 기준 시급 ≠ 활성 근로계약서 시급이면 **경고 배지**(저장은 허용, 사유 표기).
4. (선택) **약한 링크**: `PayContract.sourceContractId BigInt?` 추가 — 어느 근로계약서에서 파생됐는지 추적. 필수 아님(없어도 워커+기간으로 매칭 가능).

### 필요 확인
- 근로계약서의 **공통 필드 확정 목록**(시급/급여형태/계약기간/근무형태가 모든 템플릿에 들어가는지). → 계약서 템플릿 작업([[contract_template_todo]])과 함께 정합.
- ※ **소득유형은 근로계약서에 별도 필드로 둘 필요 없음** — §2처럼 근로자성으로 도출.

## 2. Part B — 소득유형·4대보험 자동 판정 엔진 (항목 6)

> **핵심: 소득유형도, 4대보험 가입 보험도 담당자 입력이 아니라 아래 규칙으로 계산되는 결과다.** (사용자 전달 기준 그대로 반영)
> → **새 입력 필드 불필요**(소득유형·내부/외부 토글 제거). 근로계약서 존재·근태·고용기간·근로시간으로 전부 도출.

### 판정 입력값 (전부 기존 데이터에서 도출)
- **근로자성**: 서명된 근로계약서 존재 + 출근부(출퇴근)·매니저 지시 → 근로자성 인정.
- **고용기간**: `EmploymentContract.contractStart~End` → 1개월 미만(일용).
- **월 소정근로시간/일수**: 근무형태×근로일(출근부 집계 보조) → 월 60h / 월 8일.
- **계속근로 개월수**: 최초 계약/배정 시작일~현재 → 3개월 이상(초단시간 고용보험 예외).
- **프리랜서 예외 플래그**: 근로계약 없는 건당 용역만(기본 false, 드묾).

### 판정 로직 (월별 · run 계산 시점)
```
1) 소득유형
   근로계약 + 근태(근로자성) 인정   → 근로소득(EMPLOYMENT)    ← 직무지도원 기본
   근로계약 없는 독립 프리랜서       → 사업소득(BUSINESS, 3.3%)
   ※ 근로계약 있는데 사업소득 지정   → 위법 경고/차단(임의 3.3% 처리 = 세법 위반·추징)

2) 근로소득자의 4대보험 가입 (가입 보험 집합)
   if 고용기간 < 1개월                      → 일용:     { 고용보험, 산재 }
   else if 월소정 ≥ 60h  OR  월근로일 ≥ 8일  → 일반:     { 국민연금, 건강(+장기요양), 고용보험, 산재 }
   else (월 60h 미만 & 월 8일 미만)          → 초단시간: { 산재 }  (+ 계속근로 3개월↑이면 { 고용보험 })

   사업소득(BUSINESS)                       → 4대보험 없음, 3.3% 원천징수만
```

### 워커 공제 vs 사업주 부담
- **산재보험 = 전액 사업주 부담** → 워커 공제(net) 미반영(표기만).
- **워커 공제 = 가입 보험 − 산재** (국민연금/건강/장기요양/고용 중 해당분) + (근로소득세·주민세) / (사업소득은 3.3%).

### 근거·투명성
- 판정 결과·근거(소득유형, tier, 고용기간, 월시간/일수, 계속근로개월)를 `PayrollItem.breakdown`에 저장 → 명세서·검토 화면 표기.
- 담당자는 **결과 확인만**, 예외(프리랜서 사업소득)만 명시적 오버라이드(경고 동반).

### 구현 위치
- 판정 유틸 `lib/payroll/insuranceEligibility.ts`(순수 함수, 단위테스트).
- `runs/route.ts` 공제 산정에서 호출(현 incomeType 분기 대체).
- 스키마 추가는 **`InsuranceRates` 산재 요율 컬럼 1개**(사업주 부담 표기용)뿐. 소득유형/내부외부 필드는 추가 안 함.

## 3. 정책 결정 (2026-06-16)

**✅ 확정**
1. **보험/소득 판정 = 자동 산정 + 근거 노출 + 오버라이드 허용**. 유형 판정으로 공제 자동 산정, 근거(고용기간·월시간/일수)를 명세서·breakdown에 표기, 담당자가 필요 시 수정.
1-b. **소득유형·내부/외부는 입력이 아니라 도출값**(§2). 급여 기준 폼에서 두 토글 제거, 새 스키마 필드 없음(산재 요율 컬럼만). 기존 "내부=사업소득 고정" 매핑 폐기(근로자성 기준과 충돌·위법 소지).

**잠정(반대 없으면 이대로)**
2. **사업소득 + 근로계약서 충돌** — **경고만**(등록 차단 안 함). 서명된 근로계약서가 있는 워커에 `BUSINESS` 선택 시 위법 소지 경고.
3. **산재 표기** — worker 공제 아님(사업주 부담). 명세서/리포트에 **사업주 부담분 표기, net 미반영**.
4. **초단시간 3개월 기준 시작점** — 최초 근로계약 시작일 기준.
5. **월 60h/8일 판정 기준** — 소정근로(근무형태×근로일) 기준, 출근부 실근로는 참고.

## 4. 구현 순서(설계 확정 후)

**1단계 — 정확도(무손질의 전제)**
1. (A) UI 명칭 정리 + 근로계약서 프리필 + 불일치 경고. 스키마: (선택)`PayContract.sourceContractId`.
2. (A) 근로계약서 서명 완료(CONFIRMED) 시 **급여 기준 자동 생성**(없으면) — 담당자 확인만.
3. (B) 보험 유형 판정 유틸 `lib/payroll/insuranceEligibility.ts` (입력: 고용기간·계속근로·월시간/일수 → 가입대상 집합).
4. (B) `runs/route.ts` 공제 산정에 유형별 분기 적용 + breakdown 근거 저장.
5. `InsuranceRates` 산재 요율 컬럼(표기 결정 시) + 운영자 설정 UI.
6. 사업소득 경고(급여 기준 등록 폼).

**2단계 — 자동화 동선(담당자 편의)**
7. **명세서 자동 발급**: run 확정(FINALIZED) 시 항목별 명세서 PDF 생성 + 직무지도원 앱 발급(무료 `WorkerNotice` + 워커 화면 조회). (기존 `payslip` API 재사용·일괄화)
8. **검토 화면 강화**: 계산 결과에서 이상치(보정대기·0원·전월 대비 급변·미서명 계약)만 강조 → 담당자 빠른 확인.
9. (선택) **매월 자동 트리거**: 마감일에 DRAFT 자동 생성(확정은 담당자). 크론/스케줄. 발송 비용 정책([[notification_cost_policy]]) 준수 — 앱 내 무료 우선.

## 3-b. 자동화 결정 (2026-06-16)

**✅ 확정**
6. **자동화 수준 = 계산 무인 + 발급은 1클릭 확정**. 계산·보험·세금까지 자동(DRAFT) → 담당자 이상치 검토 → "확정" 1클릭 → 명세서 자동 발급. (완전 무인 발급은 채택 안 함 — 급여 법적 책임)
7. **명세서 발급 채널 = 직무지도원 앱 내 조회(무료) + PDF 다운로드**. 이메일·알림톡 발송은 **이번 범위 제외**([[notification_cost_policy]]).

**잠정**
8. **매월 자동 트리거** — 1단계는 담당자 "이번 달 계산" 수동, 2단계에서 마감일 자동 DRAFT 생성(앱 내 무료 알림) 추가 검토.

> 마이그레이션·prisma generate 시 [[deploy_db_setup]] 주의(운영 DB 직결, dev서버 EPERM).
