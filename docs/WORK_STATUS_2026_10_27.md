## 1) 작성일 사용자 지정 (출근부만)

- 입력: `/worker/docs`(출근부 선택 시)·`/worker/docs/view`(출근부일 때)·`/pilot/docs`(출근부일 때) "작성일(선택)". 비우면 종전대로 만든 날.
- 검증 단일 출처 `checkRequestedWrittenDate`(`lib/pdf/writtenDate.ts`): 형식·실존 + 상한 = **오늘·기간 종료일 중 늦은 날**(사용자 확정: 말일까지 허용). 지난 달 분을 뒤늦게 만들 땐 오늘까지.
- 전달 경로: 워커 preview(`writtenDate` 쿼리)·generate·submit(본문), 파일럿 preview·generate(쿼리) → `buildAttendanceSheetPayload({ writtenYMD })`. 제출 스냅샷 `payload.writtenYMD`에 저장되므로 재렌더해도 불변.
- 미반영: 매니저 콘솔(admin) 문서 생성 경로.

## 2) 작성일까지 근무일 미리 채우기 (`lib/docs/attendanceSheetPayload.ts`)

- 작성일 지정 시 **오늘~min(작성일, 기간 끝)** 중 출근 행이 없는 평일을 근무형태 표준 시각·시간(`computeWorkTimes`·`dailyDocTimes`)으로 문서에 채운다. 1:多 판정도 날짜별로 동일 적용.
- 제외: 주말·공휴일·휴무일(SiteHoliday)·연차 사용일(USE)·배정 기간 밖. **지난 날 빈 칸은 '기록 누락' 신호라 채우지 않는다.**
- ★**DB(DailyAttendance)에는 쓰지 않는다** — 급여·일지 무영향. 기존 `bulk-generate`는 미래를 의도적으로 막고 출퇴근 면제 배정 전용이라 재사용하지 않았다. 출근 버튼 방식 배정도 채운다(사용자 "모든 출근부").
- 제출하면 채워진 미래 날짜도 스냅샷으로 고정된다(실제 출근이 달라져도 제출본은 불변).
- 개발 DB 실데이터 검증(오늘 10/27·작성일 10/31): 전일 4일/32h(09:00~18:00)·오전 4일/22h(08:30~14:00)·오후 4일/22h(12:30~18:00), 10/31(토) 제외, 과거 작성일은 0일 추가.

## 3) 위탁기관 담당자 수기 공란 (`lib/pdf/pdfkitRenderer.ts` `signatures()`)

- 서명 행 옵션 `handwriteBlank` — 이름이 비면 공백 **21칸(≈24mm)**. 밑줄 없음(공단 원본 서식 그대로).
- 대상: 출근부 `(공단/위탁기관) 담당자`, 훈련일지 동일, 적응지도일지 `위탁기관 담당자`, 종합평가기록부 `(위탁기관) 담당자`. **사업체담당자·직무지도원 줄은 대상 아님**(사업체담당자는 서명받을 때 이름이 들어온다).
- 파일럿도 같은 렌더러를 쓰므로 15칸(`PILOT_HANDWRITE_BLANK`)이 21칸으로 통일된다. 공백만으로는 PDF에서 안 보여 사용자가 "공란이 없다"고 본 것이 파일럿 신고의 원인이었다.
- 조정 이력: 15칸(좁다) → 30칸(넓다) → **21칸**. 밑줄은 임의로 추가했다가 사용자 지시로 제거.

## 환경·교훈

- **개발 Supabase가 프리티어 일시정지**였다가 사용자가 복구. 복구 후 마이그레이션 2건(`20261008130000_add_daily_attendance_updated_at`·`20261008140000_add_trainee_site_status_index`)이 dev에 미적용이라 `daily_attendances.updated_at` 오류가 났고, `prisma migrate deploy`로 적용(운영에는 이미 적용된 건). dev 접속 실패 시 일시정지부터 의심.
- 임시 스크립트에서 한글이 든 heredoc을 `python -` 표준입력으로 넘기면 인코딩이 깨진다 → Edit 도구 사용.
- 커밋 훅이 변경 라인의 `any`를 차단한다(테스트 파일 포함). 모킹 객체는 `Record<string, unknown>[]`로.
- 범위 해석: "이름이 없는 줄 전체"가 아니라 "위탁기관 줄만"이었다. 요청 범위를 넓게 잡지 말고 좁게 확인할 것.
