**추가 기능**(사용자 요청): 기존 "배정 취소"는 소프트 종료(행 안 지워짐)뿐이라 잘못 저장된 배정을 못 고쳤음. `updatePilotAssignment`·`deletePilotAssignment`(완전 삭제, cascade로 출근부·일지까지 제거) 신설 + `app/api/admin/pilots/[pilotId]/assignments/[assignmentId]/route.ts`(PATCH/DELETE, 파일럿 전용 레지스트리 소유권 검증, 기존 운영 API 재사용 안 함) + 파일럿 설정 화면에 수정/삭제 버튼.

## 4) 워커 홈 — 일지 작성 후 상태 미반영 버그 — `b40f087`

**사용자 발견**: 일지 작성 완료 후 홈 화면에 "미작성"으로 계속 보이다가 로그아웃·재로그인해야만 "작성완료"로 바뀜(스크린샷 2장 첨부로 제보).

**원인**: `app/worker/home/HomeClient.tsx`가 서버 프리페치(`initialData`)가 있으면 마운트 시 클라이언트 재조회를 생략(`if (!initialData) refresh()`). 일지 저장 후 `router.back()`으로 홈에 돌아오면 Next.js App Router가 떠나기 전의 캐시된 화면(stale `initialData`)을 재사용 — 재조회 조건(`!initialData`)에 안 걸려 최신 상태가 안 보임. 로그아웃 후 재로그인은 Router Cache를 안 타는 완전히 새 요청이라 최신 상태가 보였던 것.

**수정**: `initialData` 유무와 무관하게 항상 마운트 시 백그라운드로 재조회(`useEffect(() => { refresh() }, [refresh])`). `loading`은 `initialData`가 있으면 `false`로 시작해(line 267) 화면 깜빡임 없음.

**전수 조사**(사용자 요청, "동일한 상황이 발생할 수 있는 부분 전수 조사"): 이 버그 패턴(Server Component가 DB를 프리페치해 Client Component에 넘기고, Client가 조건부로 재조회를 생략)이 성립하려면 `page.tsx`가 서버에서 직접 DB/세션을 조회해야 하는데, 전체 앱에서 `next/headers`를 쓰는 `page.tsx`는 `/worker/home` 단 하나뿐임을 grep으로 확인. 유사하게 서버 프리페치 데이터를 Client Component에 넘기는 나머지 2곳(`/worker/select-site`, `/manager/invite/[code]`)도 각각 일회성 표시·URL 파라미터뿐이라 해당 없음. 나머지 전 화면은 Client Component 자체 `useEffect` + `fetch()` 구조라 뒤로가기해도 항상 새로 요청되어 이 버그에서 안전. **결론: 이번에 고친 곳이 코드베이스 전체에서 유일한 사례.**

검증: tsc 0·vitest 478/478. 브라우저 시각검증은 세션 중 브라우저 창 문제로 미실시 — **사용자가 내일 실제로 일지 작성 후 반영 여부를 확인해 알려주기로 함(결과 대기)**.
