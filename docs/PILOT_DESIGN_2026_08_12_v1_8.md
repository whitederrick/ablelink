# Able-Link 직무지도원 문서 파일럿 설계 v1.8

> 구현 기준 문서
>
> 이 문서는 `WORKER_DOCUMENT_POC` 파일럿만 다룬다.  
> 급여·근로계약·연차·`AGENCY_FULL_FLOW`·정식 운영 정책은 범위 밖이다.  
> 이전 `PILOT_DESIGN_2026_08_12_v1_7.md`는 검토 이력으로만 보존하며 구현 기준으로 사용하지 않는다.

## 1. 목적

시스템 운영자가 파일럿 환경을 미리 설정하고, 직무지도원이 일반 사용자 화면에서 다음 흐름을 실제로 수행할 수 있는지 검증한다.

1. 로그인
2. 근태·일지 작성
3. 직무지도원 서명
4. 사업체 담당자 대면 서명
5. PDF 미리보기
6. PDF 로컬 다운로드

파일럿의 목적은 위 문서 사용 흐름을 확인하는 것이다. 정식 운영 전체를 검증하거나 급여·계약 정책을 결정하는 것이 아니다.

## 2. 참여자와 역할

### 2.1 시스템 운영자

별도 `파일럿 관리` 메뉴에서 환경 전체를 설정한다.

- 파일럿 기간과 실제 위탁기관 지정
- 사업체 등록 또는 기존 사업체 선택
- 훈련생 등록
- 직무지도원 배정
- 직무지도원과 담당 훈련생 연결
- 직무지도원 초대
- 위탁기관 담당자 표시명 선택 입력
- 파일럿 근무일 확인·정정
- 회차 종료와 데이터 폐기

### 2.2 직무지도원

초대를 받아 로그인하고 기존 직무지도원 화면을 그대로 사용한다. 사업체·훈련생·배정을 직접 등록하거나 관리하지 않는다.

### 2.3 위탁기관과 담당자

- 실제 위탁기관을 회차에 반드시 지정한다.
- 시스템 운영자와 직무지도원은 어느 위탁기관인지 알고 있다.
- 위탁기관 담당자는 파일럿에 참여하지 않으며 계정도 만들지 않는다.
- 담당자 개인 이름만 모를 수 있다.
- 운영자가 이름을 알면 입력할 수 있고, 모르면 PDF에 수기 입력 공간을 둔다.

### 2.4 사업체 담당자

기존 인퍼슨 서명 흐름으로 문서에 서명한다. 위탁기관 담당자와 혼동하지 않는다.

## 3. 범위

### 3.1 포함

- `WORKER_DOCUMENT_POC` 회차 생성·셋업·종료
- 운영자 발급 직무지도원 초대
- 기존 Worker와 신규 Worker 셋업
- 사업체·훈련생·배정·재적·담당 관계 설정
- 근태·일지 작성
- 직무지도원 서명과 사업체 담당자 대면 서명
- PDF 미리보기와 로컬 다운로드
- 위탁기관 담당자 이름 인쇄 또는 수기 공란
- 파일럿 데이터 격리와 종료 후 폐기

### 3.2 제외

- 급여 계산, 급여 기준, 급여 소급 검증
- 근로계약과 연차
- `AGENCY_FULL_FLOW`
- 위탁기관 담당자 계정·승인·전자서명
- 공단 제출·발송
- PDF·ZIP·문서 링크의 이메일·알림톡·webhook 전송
- 과거 운영 데이터의 divergence 조사
- 기존 문서·급여의 소급 재계산
- 출근부 1:1·1:多 정책 변경
- 불연속 담당 기간의 정식 문서화 정책

범위 밖에서 발견되는 문제는 이 파일럿의 착수 조건으로 편입하지 않고 별도 백로그에 기록한다.

## 4. 파일럿 회차

파일럿 여부를 기관이나 기간만으로 추론하지 않는다. 같은 기관이 정상 운영을 병행할 수 있으므로 회차 ID로 명시적으로 구분한다.

```text
PilotSession
- id
- agencyId                 실제 위탁기관
- startDate / endDate      파일럿 기간
- managerDisplayName?      담당자 표시명
- status                   DRAFT / READY / ACTIVE / ENDED / PURGED / CANCELLED
- createdByAdminId
- activatedAt? / endedAt? / purgedAt?
```

규칙:

- 두 유형을 병행하지 않는다. v1에서는 `WORKER_DOCUMENT_POC`만 존재한다.
- 한 시점에 `ACTIVE` 회차는 전역 1개다.
- `DRAFT`와 `READY`에서는 셋업 정보를 수정할 수 있다.
- `ACTIVE`에서는 `managerDisplayName`만 후입력·수정할 수 있다.
- `ENDED`, `PURGED`, `CANCELLED`에서는 모든 설정을 고정한다.
- `ACTIVE` 이후 기간·기관을 변경하거나 기간을 연장하지 않는다.

## 5. 운영자 셋업

### 5.1 기존 직무지도원

```text
회차 생성(DRAFT)
→ 사업체 선택/등록
→ 기존 Worker 선택
→ 배정 생성
→ 훈련생 등록
→ 재적 생성
→ 담당 관계 생성
→ 기존 계정 연결 초대
→ 설정 검증
→ READY
→ 초대 수락
→ ACTIVE
```

### 5.2 신규 직무지도원

계정이 없으므로 배정을 먼저 만들지 않는다. 회차 참여자에 배정 설정값을 저장한 뒤 초대 수락 트랜잭션에서 계정과 관계를 생성한다.

```text
회차 생성(DRAFT)
→ 사업체·훈련생·재적 설정
→ 참여자 배정 설정값 저장
→ 설정 검증
→ READY
→ 운영자 초대 발급
→ 초대 수락 트랜잭션
   (Worker + 배정 + 담당 관계 생성)
→ ACTIVE
```

초대 수락은 `READY`에서만 허용한다. 수락 완료 후 재요청은 같은 결과를 반환하도록 멱등 처리한다. `ACTIVE` 이후에는 참여자 추가·초대 발급·수락을 허용하지 않는다.

## 6. 문서 접근 관계

파일럿 전용 권한 우회는 만들지 않는다. 운영자가 설정한 기존 도메인 관계를 접근 근거로 사용한다.

훈련생 종속 문서의 접근 범위:

```text
요청 기간
∩ 파일럿 회차 기간
∩ 직무지도원 배정 기간
∩ 훈련생 재적 기간
∩ 직무지도원-훈련생 담당 기간
```

출근부는 직무지도원 본인의 문서이므로 훈련생 재적·담당 관계를 접근 조건으로 요구하지 않는다.

파일럿 v1에서는 담당 기간을 연속된 단일 구간으로만 설정한다. 불연속 담당 기간의 문서 생성 정책은 이번 범위에서 결정하지 않는다.

출근부의 1:1·1:多 표기는 기존 2026-06-18 확정 규칙인 `해당 날짜·현장의 재적 훈련생 수`를 그대로 사용한다. 담당 관계 도입을 이유로 이 규칙이나 급여 로직을 변경하지 않는다.

## 7. 파일럿 기능 권한

파일럿 배정은 기관 구독 플랜이나 Worker의 `planType`을 임시 변경하지 않고 회차 권한으로 다음 기능만 허용한다.

```text
PDF_GENERATE
PDF_SIGN
SITE_MANAGER_SIGN
```

판정 순서:

1. 요청한 배정이 로그인한 직무지도원 소유인지 확인
2. 배정의 `pilotSessionId` 확인
3. 회차가 `ACTIVE`이고 요청 기간이 회차와 배정 범위 안인지 확인
4. 위 세 기능 중 하나이면 허용
5. 파일럿 배정인데 조건을 만족하지 않으면 거부
6. 파일럿 배정이 아닐 때만 기존 플랜 판정 사용

파일럿 배정은 일반 플랜 판정으로 폴백하지 않는다.

## 8. 문서 흐름

허용:

- PDF 미리보기
- PDF 로컬 다운로드
- 직무지도원 서명
- 사업체 담당자 대면 서명
- 근태·일지 작성

차단:

- 직무지도원의 위탁기관 최종 제출
- 위탁기관 승인·서명
- 공단 발송
- PDF 이메일 발송
- ZIP 이메일 발송
- 문서 링크 알림톡
- 문서 데이터 webhook

직무지도원 화면에서는 `[위탁기관에 최종 제출]` 대신 `[파일럿 PDF 다운로드]`를 표시한다. 서버에서도 제출과 외부 전송을 차단한다.

직무지도원 계정 발급에 필요한 초대 SMS는 허용한다. 이는 문서 외부 전송이 아니다.

## 9. PDF 담당자 이름과 서명

`managerDisplayName`은 위탁기관 담당자 계정이나 전자서명이 아니라 PDF 표시용 문자열이다.

| 상태 | 위탁기관 담당자 이름란 | 위탁기관 담당자 서명란 |
|---|---|---|
| 표시명 입력 | 이름 인쇄 | 공란 |
| 표시명 미입력 | 고정 폭 수기 입력 공간 | 공란 |

문서 슬롯:

- 출근부·지원고용 훈련일지·적응지도 일지: `govAgent.name`
- 훈련생 종합평가·적응지도 종합평가: `agencyAgent.name`
- `companyManager`: 주입 금지. 기존 사업체 담당자 이름·대면 서명 흐름 유지

미리보기와 다운로드는 같은 담당자명 생성 함수를 사용해 동일하게 출력한다. 담당자 서명 공간은 이름 입력 여부와 관계없이 유지한다.

## 10. 근무일 처리

직무지도원이 실제로 근무한 날짜만 문서에 포함되어야 한다. 위탁기관 담당자가 없는 파일럿에서 기존 매니저 승인 경로에 의존하지 않도록 운영자 파일럿 관리 화면에서 회차 근무일을 확인·정정할 수 있게 한다.

- 오늘까지의 근무일: 생성·수정·삭제 가능
- 미래 근무일: 사전 생성하지 않음
- 일지가 연결된 근무일 삭제: 연관 데이터 확인 후 차단 또는 명시 처리
- 변경은 해당 파일럿 회차의 배정에만 적용

## 11. 데이터 격리와 폐기

운영 데이터에는 `pilotSessionId`를 명시적으로 기록한다. 기관+기간 또는 생성 시각으로 파일럿 데이터를 추론하지 않는다.

회차가 새로 만든 공유 자원은 `createdByPilotSessionId`로 구분한다.

정상 운영 자동화(월간 급여 DRAFT 생성 cron, 연차 자동 적립)는 파일럿 배정과 파일럿 생성 Worker를 제외한다. 이 필터는 자동화가 데이터를 생성하기 전에 적용한다.

삭제 가능:

- 파일럿 전용 초대
- 배정·재적·담당 관계
- 근태·일지
- 파일럿 PDF·서명 이미지·토큰
- 회차가 새로 만든 Site·Trainee 중 다른 정상 참조가 없는 자원

보존:

- 실제 Agency
- 기존 Worker
- 재사용한 Site·Trainee
- 감사 로그(자유 입력 PII만 비식별화)
- PilotSession과 참여 이력

파일럿에서 생성한 신규 Worker는 hard delete하지 않는다. 다른 정상 배정이 없으면 `PAUSED`로 전환하고 `sessionVersion`을 증가시켜 로그인을 차단한다.

폐기 완료 후 회차를 `PURGED`로 전환하고 `purgedAt`을 기록한다.

## 12. 구현 순서

1. 직무지도원-훈련생 담당 관계와 기간 검증 구현
2. 파일럿 회차·참여자·회차 FK 스키마
3. 운영자 초대와 신규 Worker 수락 트랜잭션
4. 운영자 파일럿 관리·셋업 화면
5. 파일럿 기능 권한
6. 제출·외부 전송 차단
7. PDF 담당자명·수기 공란·슬롯 매핑
8. 운영자 근무일 확인·정정
9. 폐기 기능과 테스트

도메인 관계 마이그레이션과 파일럿 운영 메타데이터 마이그레이션은 분리한다.

## 13. 완료 조건

- 운영자가 실제 기관·사업체·훈련생·직무지도원을 회차에 설정할 수 있다.
- 신규·기존 직무지도원 모두 운영자 초대로 진입할 수 있다.
- 직무지도원이 일반 화면에서 근태·일지를 작성할 수 있다.
- 직무지도원과 사업체 담당자 서명이 정상 반영된다.
- 담당자 이름을 입력하면 PDF에 표시되고, 미입력하면 수기 공간이 나온다.
- 미리보기와 다운로드 결과의 담당자 이름이 일치한다.
- 최종 제출과 모든 문서 외부 전송이 서버에서 차단된다.
- 같은 기관의 정상 운영 데이터가 파일럿으로 오인되지 않는다.
- 종료 후 파일럿 데이터만 폐기되고 정상 자원은 보존된다.

- `AGENCY_FULL_FLOW`
- 급여·계약·연차 스코프
- 1:1·1:多 기준 변경 검토
- 운영 데이터 divergence 조사
- 과거 문서·급여의 소급 정책
- 불연속 담당 기간의 정식 문서화 방식
- 외부 전송 승인 기능
