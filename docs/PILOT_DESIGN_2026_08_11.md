## 1. 시나리오 1 — 직무지도원 단독 사용 파일럿

### 목표 흐름
파일럿 초대 링크로 가입 → **사업체 직접 등록** → **훈련생 직접 등록** → 출근부 자동 생성
→ 일지 작성 → 사업체 담당자 인퍼슨 사인 → PDF 생성(위탁기관 담당자란 = 수기/입력) → (공단 발송은 차단)

### 현재 상태 갭
| 단계 | 현재 | 갭 |
|---|---|---|
| 가입 | ❌ 셀프 가입(OTP) 2026-06-06 폐쇄(403). 초대 코드 가입(`auth/register`)만 동작 | **파일럿 기관 초대 발급으로 해결 — 신규 코드 거의 불요** |
| 사업체 등록 | ❌ `worker/site/register` 2026-06-06 의도적 종료(403) | **파일럿 전용 신설 필요** |
| 훈련생 등록 | ❌ 매니저 전용 | **워커용 신설 필요** |
| 현장 배정 | ❌ 매니저 생성 + 인증코드 연결 구조 | **사업체 등록 시 자동 생성 필요** |
| 출근부 | ✅ `worker/attendance/bulk-generate` (attendanceButtonExempt 필요) | 배정만 맞으면 동작 |
| 일지 | ✅ 수동 + AI 음성 | 없음 |
| 사업체 사인 | ✅ `worker/docs/inperson-sign` (SiteSignToken) | 없음 |
| 위탁기관 담당자란 | ❌ 미구현 (설계만) | **PDF 렌더 수정 필요** |

### 기존 자산 활용 (조사 확인)
- **`SiteSourceType.WORKER_ENTRY` + `isVerified` + 병합 링크(`mergedToSiteId`)가 스키마에 이미 존재** —
  직무지도원 입력 현장을 위한 인프라가 준비돼 있음. 셀프 등록 Site는 `WORKER_ENTRY`/`isVerified=false`로 생성.
- 기존 403 라우트(`app/api/worker/site/register`)는 **그대로 유지** — 정체성 모델(실운영은 기관이 배정) 불변.
  파일럿은 별도 네임스페이스(`/api/worker/pilot/*`)로 신설해 격리.

### 작업 분해

**W1. 파일럿 기관 시드 + 식별 플래그** *(S)*
- `Agency.isDemo Boolean @default(false)` 컬럼 추가(마이그레이션) + 파일럿 기관 1개 시드.
- `planType=PRO`(기능 게이트 전부 통과), 마켓플레이스/모집/통계/운영 목록에서 `isDemo` 제외.

**W2. 파일럿 진입 = 기존 초대 플로우 재사용** *(S)*
- 셀프 가입이 폐쇄돼 있으므로(v1.1 정정) 오히려 단순해짐: **파일럿 기관 명의로 기존 WorkerInvite 발급**
  (siteId 미지정, 24h·6자리 코드) → 테스터가 초대 링크로 가입. 소수 테스터 통제와도 정확히 부합.
- 파일럿 참여자 판정: 파일럿 기관 초대로 가입했는지(`WorkerInvite.usedByWorkerId` + 발급 기관) 기준.
- 홈에 "파일럿 모드" 배지 + 사업체/훈련생 등록 메뉴 노출.

**W3. 사업체(현장) 셀프 등록** *(M — 핵심)*
- `POST /api/worker/pilot/sites` — Site 생성(`WORKER_ENTRY`, `isVerified=false`, `agencyId=파일럿기관`,
  주소→GPS 지오코딩 기존 로직 재사용, 사업체 담당자 이름/연락처 입력 포함)
- **동시에 본인 SiteAssignment 자동 생성**: `status=ACTIVE`, `attendanceButtonExempt=true`,
  `connectedAt=now`, `agencyId=파일럿기관`, 근무형태·기간은 폼에서 입력.
- UI: `/worker/pilot/sites/new` 등록 폼 (기존 매니저 현장 등록 폼 참고).

**W4. 훈련생 셀프 등록** *(M)*
- `POST /api/worker/pilot/trainees` — Trainee + TraineePlacement 생성.
- 가드: 본인이 등록한 파일럿 스코프(`WORKER_ENTRY` + 파일럿 기관) 현장에만 등록 가능.
- UI: 사업체 상세에서 훈련생 추가/수정.

**W5. PDF 위탁기관 담당자 수기란** *(S~M)*
- 문서 생성 시 선택 입력 `agencyManagerName` → 있으면 담당자란에 인쇄, 없으면 밑줄 빈칸 렌더.
- 서명(인) 자리는 항상 빈칸(종이 수기용). 구현은 "manager 서명 데이터 없는 문서" 일반 규칙으로.
- 대상 PDF: 출근부·훈련일지·종합평가·적응지도 일지·적응지도 평가 5종의 위탁기관 담당자란.

**W6. 공단 발송 하드블록** *(S)*
- `docs/submit`·문서 이메일 발송 경로에서 `agency.isDemo` → 403 차단. (7/19 설계 E 그대로)

**W7. 정리 스크립트** *(S)*
- `scripts/cleanup-pilot.mts` — 파일럿 기관 스코프 데이터 일괄 삭제(수동 실행). 소수 테스터라 자동화 불요.

### ⚠️ 기술 주의 (7/19 문서에서 승계 — 필수)
- 출근부 페이로드는 `startTime=null` 행 제외(`lib/docs/attendanceSheetPayload.ts:77`).
  → 파일럿 근태는 반드시 **`bulk-generate`(startTime 채움)** 경로로 생성. `logs/save` 자동근태만으로는 출근부가 빈다.
- W3의 자동 배정이 `attendanceButtonExempt=true`여야 `bulk-generate` 403 가드를 통과한다.
- 출근부 시각 = 근무형태(`dailyDocTimes`) 단일 출처 → W3 폼에서 근무형태(AM/PM/FULL_DAY/CUSTOM) 입력 필수.
