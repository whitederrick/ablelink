# Able-Link 사용자 매뉴얼 - 시스템 운영자

문서 버전: v0.9 draft  
대상 사용자: 시스템 운영자  
작성 기준: 2026-07-03 현재 코드 기준  
주의: 시스템 운영자는 전체 기관과 개인정보에 접근할 수 있으므로, 모든 작업은 업무 목적과 감사 가능성을 전제로 수행해야 합니다.

---

## 1. 이 매뉴얼의 목적

이 문서는 Able-Link 시스템 운영자가 서비스를 운영하면서 수행해야 하는 주요 업무를 프로세스 흐름에 따라 설명합니다.

시스템 운영자의 기본 업무는 다음과 같습니다.

1. 운영자 로그인
2. 위탁기관 생성/승인/관리
3. 위탁기관 관리자 계정 관리
4. 전체 현장/직무지도원/훈련생 상태 확인
5. 전체 근태/문서/계약/급여 상태 모니터링
6. 시스템 공지와 지원 요청 처리
7. 구독/결제/사용량 관리
8. 운영 설정, 세액표, 보험요율 관리
9. 감사로그와 개인정보 접속기록 확인
10. 백업과 장애 대응
11. 출시/배포 후 점검

---

## 2. 시스템 운영자 로그인

### 2.1 접속 경로

- 로그인: `/admin/login`
- 로그인 후 대시보드: `/admin`

### 2.2 로그인 절차

1. 시스템 운영자 로그인 화면으로 이동합니다.
2. 운영자 ID와 비밀번호를 입력합니다.
3. 로그인을 선택합니다.
4. 시스템 관리자 대시보드로 이동합니다.

### 2.3 운영자 계정 보안 원칙

- 운영자 계정은 개인별로 발급합니다.
- 공용 운영자 계정을 사용하지 않습니다.
- 퇴사자 또는 담당 변경자는 즉시 비활성화합니다.
- 비밀번호 초기화 이력은 감사 대상입니다.
- 운영자 화면은 전체 개인정보 접근이 가능하므로 공용 PC에서 사용하지 않습니다.

## 3. 운영 대시보드 확인

### 3.1 관련 메뉴

- 시스템 대시보드: `/admin`

### 3.2 매일 확인할 항목

| 항목 | 확인 내용 | 조치 |
|---|---|---|
| 위탁기관 상태 | 신규/활성/비활성 기관 | 가입 승인 또는 지원 |
| 직무지도원 현황 | 활성 인원, 배정 상태 | 기관 문의 대응 |
| 근태 상태 | 지각, 조퇴, 미출근, 퇴근 미실행 | 기관 관리자 처리 유도 |
| 문서 마감 | 제출/확정/발송 상태 | 마감 독려 |
| 계약 상태 | 미서명/만료 예정 | 기관 안내 |
| 결제/구독 | 결제 실패, 플랜 상태 | 결제 안내 |
| 지원 요청 | 미답변 문의 | 회신 또는 내부 조치 |

### 3.3 월말 집중 확인

월말에는 다음을 우선 확인합니다.

1. 종료 예정 배정의 출근부/일지 완료 여부
2. 문서 제출/확정/공단 발송 상태
3. 급여 run 생성과 확정 상태
4. 보정대기 근태 잔여 건
5. 기관별 문의/장애 건

## 4. 위탁기관 관리

### 4.1 관련 메뉴

- 위탁기관 관리: `/admin/agencies`
- 위탁기관 상세: `/admin/agencies/[id]`
- 위탁기관 관리자 가입요청: `/admin/manager-signup-requests`

### 4.2 신규 위탁기관 생성

1. 위탁기관 관리 메뉴로 이동합니다.
2. 신규 기관 등록을 선택합니다.
3. 기관명, 사업자정보, 주소, 연락처를 입력합니다.
4. 구독 플랜과 사용 한도를 확인합니다.
5. 저장합니다.
6. 기관 상세에서 정보가 올바른지 확인합니다.

### 4.3 가입요청 승인

1. 위탁기관 관리자 가입요청 메뉴로 이동합니다.
2. 신청자 정보와 기관 정보를 확인합니다.
3. 사업자 서류가 있으면 확인합니다.
4. 승인 또는 반려를 선택합니다.
5. 승인 시 관리자 계정 생성 또는 초대 상태를 확인합니다.

승인 전 확인:

- 기관명이 실제 기관과 일치하는지
- 사업자등록번호/서류가 맞는지
- 신청자가 기관 담당자인지
- 연락처와 이메일이 맞는지
- 중복 기관이 없는지

### 4.4 기관 수정/비활성화

기관 정보를 수정할 때는 다음 영향을 확인합니다.

| 변경 항목 | 영향 |
|---|---|
| 기관명 | 계약서, 문서, 이메일 발송문 |
| 대표자 정보 | 계약서 사업주 정보 |
| 담당자 이메일 | 공단/문서 발송 수신 |
| 구독 플랜 | 기능 접근 권한 |
| 관리자 계정 | 기관 접근 가능 여부 |

기관 운영을 중단할 때는 삭제보다 비활성화 또는 구독 정지를 우선합니다. 이미 생성된 출근부, 계약서, 급여, 문서는 법정 보존 대상일 수 있습니다.

## 5. 위탁기관 관리자 계정 관리

### 5.1 관련 메뉴

- 위탁기관 관리자 가입요청: `/admin/manager-signup-requests`
- 위탁기관 상세 관리자 영역
- 시스템 관리자/매니저 API 관리 화면

### 5.2 관리자 초대/생성 절차

1. 대상 위탁기관을 선택합니다.
2. 관리자 이름, ID, 이메일, 전화번호를 입력합니다.
3. 초대 링크 또는 임시 비밀번호를 발급합니다.
4. 담당자에게 전달합니다.
5. 최초 로그인 여부를 확인합니다.

### 5.3 관리자 권한 회수

1. 기관 상세에서 관리자 목록을 확인합니다.
2. 권한 회수 대상 계정을 선택합니다.
3. 비활성화합니다.
4. 필요 시 세션 만료 또는 비밀번호 초기화를 진행합니다.

주의:

- 위탁기관 관리자는 자기 기관 전체 개인정보에 접근할 수 있습니다.
- 담당자 퇴사 또는 외주 종료 시 즉시 비활성화해야 합니다.

---

## 6. 전체 직무지도원 관리

### 6.1 관련 메뉴

- 직무지도원 현황 관리: `/admin/workers`
- 직무지도원 계정 관리: `/admin/worker-accounts`
- 자격 검증: `/admin/professions`

### 6.2 운영자가 확인할 수 있는 정보

- 직무지도원 이름
- 전화번호/로그인 ID
- 소속 위탁기관
- 현장 배정 상태
- 계정 상태
- 구독/개인 권한
- 계좌/본인확인 상태
- 자격 검증 상태

### 6.3 비밀번호 초기화

운영자가 비밀번호를 초기화할 수 있습니다.

절차:

1. 직무지도원 상세를 엽니다.
2. 비밀번호 초기화를 선택합니다.
3. 임시 비밀번호를 확인합니다.
4. 안전한 경로로 기관 담당자 또는 본인에게 전달합니다.
5. 전달 후 비밀번호 변경을 안내합니다.

보안 주의:

- 임시 비밀번호를 공개 채팅방에 남기지 않습니다.
- 임시 비밀번호 발급 사유를 기록합니다.
- 운영자는 직무지도원 대신 로그인하지 않습니다.

## 7. 전체 현장과 훈련생 관리

### 7.1 관련 메뉴

- 현장 관리: `/admin/sites`
- 현장 상세: `/admin/sites/[id]`
- 훈련생 현황: `/admin/trainees`

### 7.2 확인할 항목

| 대상 | 확인 내용 |
|---|---|
| 현장 | 기관, 주소, GPS 기준점, 허용 반경, 근무형태 |
| 담당자 | 사업체 담당자, 공단 담당자, 추가 담당자 |
| 훈련생 | 현장, 배치 기간, 상태 |
| 배정 | 담당 직무지도원, 시작/종료일, 상태 |

### 7.3 운영자 개입이 필요한 경우

- 기관이 현장 GPS를 잘못 설정해 출근 오류가 반복될 때
- 훈련생 배치 기간 오류로 문서/급여가 틀어질 때
- 기관 간 현장/훈련생 스코프가 잘못 연결된 것으로 의심될 때
- 멀티현장 배정에서 문서 또는 급여 오류가 발생할 때

## 8. 근태 모니터링

### 8.1 관련 메뉴

- 근태 현황 관리: `/admin/attendances`
- 월별 진척/리뷰: `/admin/review`

### 8.2 운영자가 확인하는 이유

시스템 운영자는 개별 근태를 직접 처리하기보다는, 기관이 제대로 처리하고 있는지 모니터링합니다.

확인 대상:

- 미출근/결근 합성 표시
- 지각/조퇴 이슈
- 퇴근 미실행
- 보정대기 잔여 건
- 출근부 수정 요청 처리 지연
- 월말 문서 마감 지연

### 8.3 기관 독려

월말에 미확정 건이 남아 있으면 기관 관리자에게 독려 알림을 보냅니다.

독려 대상:

- 근무 종료 예정 직무지도원의 출근부 미확정
- 일지 미완료
- 문서 미제출
- 공단 발송 미완료

---

## 9. 계약과 문서 운영 모니터링

### 9.1 관련 메뉴

- 계약서 현황 관리: `/admin/contracts`
- 문서 생성/미리보기/서명 API 기반 화면
- 감사 패키지: `/admin/audit-package`
- 공단 제출 이력: 기관 관리자 화면과 API

### 9.2 계약 모니터링

확인 항목:

- 미서명 계약
- 만료 예정 계약
- 취소된 계약
- 배정과 연결되지 않은 계약
- 계약 서명 후 배정 상태가 이상한 경우

### 9.3 문서 모니터링

확인 항목:

- 제출 대기
- 관리자 검토 대기
- 변경 요청 중
- 관리자 서명 대기
- 공단 발송 대기
- 공단 발송 완료

운영자가 개입할 상황:

- 기관이 문서 발송을 못 하는 경우
- PDF 생성 오류가 발생하는 경우
- 서명 이미지가 표시되지 않는 경우
- 문서에 다른 현장/훈련생 정보가 들어간 것으로 의심되는 경우
- 감사자료 요청이 들어온 경우

## 10. 급여 운영 모니터링

### 10.1 관련 메뉴

- 급여 관련 API/관리 화면
- 기관 관리자 급여 메뉴: `/manager/payroll`
- 운영자 설정: `/admin/settings/income-tax`, `/admin/settings/insurance-rates`

### 10.2 운영자 역할

운영자는 기관의 급여 산정 작업을 직접 대행하기보다는, 계산 기준과 설정값을 관리하고 장애를 지원합니다.

확인 항목:

- 세액표 업로드 상태
- 보험요율 설정
- 급여 run 생성 오류
- 임금명세서 PDF 오류
- 급여 계산 정책 변경 사항

### 10.3 급여 관련 주의

다음 항목은 정책 확정 없이 운영자가 임의로 자동화하면 안 됩니다.

- 국민연금/건강보험 자동공제 승격
- 표준소득월액 등급표
- 부분월 월급 차감 정책
- 유급휴일/공휴일/커스텀휴무 급여 정책
- 같은 기관 재지급/배정별 PayContract 정책

## 11. 시스템 공지와 프로모션 관리

### 11.1 관련 메뉴

- 시스템 공지: `/admin/announcements`
- 공지 카테고리: `/admin/settings/categories`
- 대시보드 프로모션: `/admin/promos`

### 11.2 시스템 공지 작성 기준

시스템 공지는 다음 상황에 사용합니다.

- 서비스 점검
- 장애 안내
- 기능 업데이트
- 약관/개인정보처리방침 변경
- 급여/문서 정책 변경
- 월말 마감 안내

작성 시 주의:

- 특정 기관의 개인정보를 포함하지 않습니다.
- 장애 원인을 확정하지 못했으면 추정 표현을 피합니다.
- 점검 시간, 영향 범위, 조치 방법을 명확히 씁니다.

### 11.3 프로모션 관리

프로모션은 기관 관리자 대시보드에 노출되는 안내 영역입니다.

사용 예:

- 신규 기능 소개
- 구독 업그레이드 안내
- 월말 문서 마감 캠페인
- 공지사항 강조

---

## 12. 지원 요청 처리

### 12.1 관련 메뉴

- 지원 요청: `/admin/support`

### 12.2 처리 절차

1. 지원 요청 목록을 확인합니다.
2. 기관명, 요청자, 제목, 내용을 확인합니다.
3. 첨부파일이 있으면 필요한 경우에만 열람합니다.
4. 단순 사용법 문의는 답변합니다.
5. 데이터 오류 또는 버그는 개발 이슈로 분류합니다.
6. 회신을 작성합니다.
7. 처리 상태를 완료로 변경합니다.

### 12.3 문의 유형별 처리

| 유형 | 예 | 처리 |
|---|---|---|
| 사용법 | 문서 발송 방법 문의 | 매뉴얼 안내 |
| 데이터 오류 | 출근부가 이상함 | 현장/배정/근태 데이터 확인 |
| 권한 오류 | 메뉴 접근 불가 | 계정/구독/기관 스코프 확인 |
| 결제 오류 | 결제 실패 | 결제 로그 확인 |
| PDF 오류 | 서명이 안 보임 | 서명 URL/스토리지/PDF 로그 확인 |
| 급여 오류 | 금액이 다름 | 급여계약/근태/정책 확인 |

개인정보 주의:

- 첨부파일을 로컬에 내려받은 경우 처리 후 삭제합니다.
- 회신에 계좌번호, 토큰, 비밀번호 전체를 적지 않습니다.
- 다른 기관 정보가 섞인 화면 캡처는 공유하지 않습니다.

## 14. 운영 설정 관리

### 14.1 관련 메뉴

- 운영 설정값: `/admin/settings`
- 간이세액표: `/admin/settings/income-tax`
- 보험요율: `/admin/settings/insurance-rates`
- 공지 카테고리: `/admin/settings/categories`

### 14.2 설정 변경 절차

1. 변경할 설정을 찾습니다.
2. 현재 값을 기록합니다.
3. 새 값을 입력합니다.
4. 저장합니다.
5. 관련 기능을 샘플로 확인합니다.
6. 변경 내용을 내부 운영 채널에 공유합니다.

### 14.3 주요 설정

| 설정 | 영향 |
|---|---|
| AI 일괄 일지 월 허용 횟수 | 직무지도원 AI batch 사용 제한 |
| 출근부 자동 마감 분 | 퇴근 후 자동 확정 기준 |
| 문서 버전 보존 수 | 문서 이력 보관 개수 |
| 무료 체험 기간 | 신규 기관 trial 기간 |
| 지각 인정 기준 | 기본 지각 표시 기준 |
| 홈 화면 문구 | 직무지도원 홈 안내 문구 |

### 14.4 급여 설정

급여 관련 설정은 변경 전 반드시 영향 범위를 확인합니다.

- 간이세액표
- 4대보험 요율
- 공제 정책
- 주휴수당 정책

운영 기준:

- 세액표와 보험요율 변경은 시행일 기준을 남깁니다.
- 변경 후 샘플 급여를 재계산합니다.
- 기관에 공지할 필요가 있는 변경은 시스템 공지를 작성합니다.

## 18. 장애 대응

### 18.1 장애 접수 시 기본 질문

1. 어느 기관인가?
2. 어느 사용자 계정인가?
3. 어떤 메뉴인가?
4. 언제 발생했는가?
5. 어떤 작업을 하던 중인가?
6. 에러 메시지는 무엇인가?
7. 재현 가능한가?
8. 개인정보가 포함된 화면 캡처인가?

### 18.2 장애 유형별 우선 확인

| 장애 | 우선 확인 |
|---|---|
| 로그인 실패 | 계정 상태, 세션 secret, 쿠키, 비밀번호 |
| 권한 오류 | agencyId, managerId, workerId, assignmentId |
| 출근 실패 | 현장 배정, GPS 권한, 현장 기준점 |
| 일지 누락 | 훈련생 배치, 날짜, trainingType |
| 문서 오류 | payload, 서명 URL, PDF renderer |
| 이메일 실패 | SES 설정, 수신자, 첨부 용량 |
| 알림톡 실패 | 템플릿 코드, 발신 프로필, 전화번호 |
| 급여 오류 | PayContract, 근태 확정, 보정대기, 세액표 |
| 결제 오류 | Toss key, billing key, 결제 로그 |

### 18.3 임시 조치 원칙

- 개인정보 원본을 개발자에게 직접 전달하지 않습니다.
- 운영 DB를 직접 수정하기 전 백업과 변경 사유를 남깁니다.
- 급여/계약/문서 데이터는 임의 수정하지 않고 재생성/버전 처리 원칙을 따릅니다.
- 긴급 조치 후 원인과 재발방지 항목을 기록합니다.
