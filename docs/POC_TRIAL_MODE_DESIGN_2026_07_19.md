# PoC 직무지도원 "체험 모드" 설계 (2026-07-19, 논의 중 — 미착수)

## 배경 · 의도
- **실운영 환경**에서, 사전 세팅(현장배정 · 위탁기관담당자 · 사업체담당자)을 **전부 건너뛰고** 직무지도원이 **혼자 전 흐름을 체험/테스트**할 수 있게 한다.
- 원래 PoC용 데이터를 손으로 만들다가 "풀 기능이 안 돌아" 진행 불가 → 운영 DB 초기화(2026-07-19). 그 재발 방지 + 체험 상시화가 목적.
- 이건 "실데이터 세팅"도 "운영자 저작도구"도 아니다 — **직무지도원이 남의 세팅 없이 바로 체험**하는 격리된 환경.

## 확정된 요구 (사용자, 2026-07-19)
- ✅ **여러 사람이 각자** 체험 (= 자가 프로비저닝).
- ✅ 디지털 서명 = **사업체 담당자만** (직무지도원이 인퍼슨=폰 전달로 직접 서명 — 이미 가능).
- ✅ **위탁기관 담당자는 디지털 서명 없음.** 대신 **PDF 문서에 이름을 손으로 적을 빈 칸(수기 기입란)** 필요.
- ✅ 체험 데이터는 실운영 오염 금지(실기관 화면 · 마켓플레이스 · **공단 발송** · 통계).

## 전 흐름과 각 단계 전제 (조사 결과)
| 단계 | 직무지도원이 하는 일 | 필요한 전제(=자동 제공 대상) | 현재 |
|---|---|---|---|
| 일지 작성 | 훈련생 골라 일지 입력 | 현장 배정 + 훈련생 등록 | 매니저가 만들어야 함 → **자동 제공 필요** |
| 출근부 | 자동 생성(출퇴근 미사용) | `attendanceButtonExempt` 배정 | **이미 있음** — `worker/attendance/bulk-generate`가 근무형태 시각으로 출근부 생성 |
| 사업체 사인 | 폰에 직접 서명 | 사업체 담당자 | **이미 가능** — `worker/docs/inperson-sign` (막힘 아님) |
| 제출·위탁기관 사인 | (디지털 사인 없음) | 위탁기관 담당자 | **PDF 수기 기입란으로 대체** |

→ **실제로 "건너뛰어 자동 제공"이 필요한 건 3개뿐**: ① 체험 현장 ② 훈련생 ③ 그 현장 활성 배정(출퇴근 면제).

## 제안 설계 (구체안)
- **A. 체험용 위탁기관 1개** — 운영에 1회 시드, `isDemo` 플래그. 마켓/모집 노출 제외 · 공단 발송 하드블록 · 기관 스코프로 실기관 화면 자연 격리.
- **B. 자가 프로비저닝** — 직무지도원 앱 "체험 시작" → 본인에게 체험 현장(출퇴근 면제)+훈련생 1~2명+활성 배정(기간 넉넉) 자동 발급. 재실행 시 기존 체험셋 재사용(중복 방지).
- **C. 체험 흐름 = 기존 직무지도원 화면 그대로** — 출근부 일괄생성 · 일지 작성 · 사업체 인퍼슨 사인 · 문서/PDF 생성 전부 기존 재사용.
- **D. PDF** — 위탁기관 담당자란을 **수기 기입용 빈 칸**("위탁기관 담당자: ________ (인)")으로 렌더.
- **E. 공단 발송 차단** — 체험 기관 문서는 발송 API에서 하드블록.

→ **신규 작업은 3곳**: ① 체험 기관 시드 ② "체험 시작" 프로비저닝 엔드포인트+진입 ③ PDF 수기란 + 발송 하드블록.

## ⛔ 열린 결정 (미정 — 이거 정하면 착수)
1. **체험자 범위** — 불특정 다수(공개, 남용방지·자동정리 필요) vs 아는 파일럿 테스터 소수(정리 느슨). → 남용방지·정리 투자량 결정.
2. **PDF 수기란 적용 범위** — 체험 문서에만 vs 매니저 서명 없는 모든 문서에 일반 적용.

## 재사용할 기존 자산 (조사 확인)
- `worker/attendance/bulk-generate` — 출퇴근 없이 근무형태 표준시각으로 `DailyAttendance` 일괄생성. **단 `attendanceButtonExempt` 배정만 허용**(403 가드). 주말·공휴일·커스텀휴무·기간밖 자동제외.
- `worker/logs/save` — 일지 저장. `findOrCreateAttendance`가 근태 자동생성 가능하나 **startTime=null**.
- `worker/docs/inperson-sign` — 사업체 담당자(company_manager) 인퍼슨 서명(SiteSignToken).
- 서명 슬롯 4종: worker · company_manager(SiteSignToken) · manager(`managerSignatureUrl`) · agency(`agencySignatureUrl`). signStage: DRAFT→WORKER_SIGNED→MANAGER_SIGNED→SUBMITTED→AGENCY_SIGNED.

## ⚠️ 중요 기술 주의 (설계 반영 필수)
- **출근부 페이로드는 `startTime=null` 행을 제외**한다(`lib/docs/attendanceSheetPayload.ts:77`, 문서 8h↔급여 0h 불일치 방지 P2 장치). → 체험 근태는 반드시 **`bulk-generate`(startTime 채움)로 생성**해야 출근부에 표기됨. `logs/save`의 자동근태(startTime=null)만으로는 출근부가 빈다.
- `computeRun`도 `startTime=null` 제외(급여). 체험이 급여까지 포함하면 별도 고려(현재 요구엔 급여 없음).
- 출근부 시각 출처 = 근무형태(`dailyDocTimes`/`computeWorkTimes`) 단일출처. 클록인 시각 아님 → 스케줄 시각으로 정상 표기.
